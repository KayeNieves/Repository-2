### Git Commands and Workflow

The activity introduced the following Git commands and their purposes:

**1. Clone the Repository**

```bash
git clone <repository-url>
```

Clones a remote repository to a local computer, allowing a contributor to work on the project files locally.

**2. Check the Repository Status**

```bash
git status
```

Displays the current state of the working directory and indicates whether files have been modified, added, or staged.

**3. Pull Updates**

```bash
git pull origin main
```

Retrieves and integrates updates from the remote `main` branch into the local branch, helping keep the local copy up to date.

**4. Stage Changes**

```bash
git add .
```

Stages modified and new files so they can be included in the next commit.

**5. Commit Changes**

```bash
git commit -m "Update collaboration text"
```

Records the staged changes in the local repository with a descriptive message.

**6. Push Changes**

```bash
git push origin main
```

Uploads committed changes from the local `main` branch to the remote repository on GitHub.

*Note: These commands illustrate the typical Git collaboration workflow. The exact commands used may differ depending on whether changes were made directly on GitHub, through GitHub Desktop, or through the command line.*

### Key Concepts Learned

- **Git:** A version control system used to track changes in files.
- **GitHub:** An online platform for hosting repositories and collaborating on projects.
- **Clone:** Creating a local copy of a remote repository.
- **Pull:** Retrieving and integrating remote changes.
- **Add and Commit:** Preparing and recording changes in the local repository.
- **Push:** Uploading committed changes to a remote repository.
- **Collaboration:** Allowing multiple contributors to work on a shared project.
- **Version Control:** Tracking changes and maintaining a history of project modifications.
